# 007: Same-pool conditional-likelihood selection

Status: causal-alignment tests and the eight-cell development runtime pilot completed; the 189-cell pilot is running. Outputs remain unjudged. This E3 experiment uses existing N8 prefixes and generates no new O-lens samples. No paid API calls.

The selector asks whether a capped complete candidate is more likely under its true activation than under matched controls. Each candidate is teacher-forced through the frozen released O-lens with the exact `concepts_raw` carrier, layer condition, and unit-normalized injection of16000. Neither the target prompt/transcript nor known answers enter the carrier. The average candidate-token log likelihood is compared with the mean over the **first two controls** in the already frozen development control bank. Totals, actual lengths, individual token log probabilities and all conditional scores are retained. EOS is excluded consistently. This is a two-control pilot, not a silently enlarged or replaced bank.

Every method uses the same first8 existing candidates, source-preserving contiguous-bullet parsing, maximum4 bullets and256 Qwen tokens. Parsing-ineligible candidates remain explicit exclusions. Candidate length is identical across its true/control conditions; token averaging is the fixed primary normalization. The same-pool exact-AR A8 output is retained as a comparator.

Two baselines require no additional forwards: selecting by highest own-activation average likelihood, and selecting by highest mean matched-control average likelihood (a proxy independent of this target activation). These help distinguish contrastive information from general fluency/wording preferences. All final outputs receive blind evaluation later; no judge verdict feeds this selection.

`src/olens_improve/contrastive.py` implements independent same-layer batched rows. `tests/test_likelihood_alignment.py` checks that the carrier's final logit predicts the first candidate token, later candidate logits shift correctly, and padding is excluded. The production singleton wrapper calls the same batching implementation. Runtime validation crosses candidate lengths and target/control activations; it compares batched scores with singleton forwards before the pilot.

The eight-cell instrument had batch/singleton absolute mean-log-likelihood differences of **.004609, .002769 and .002673 nats/token**, below the predeclared provisional .05 guard. It took **40.36 seconds total and8.54 seconds for scoring** on the extra preemptable H20025459615. This projected roughly202 seconds of scoring for189 cells, plus setup, supporting the bounded expansion. Passing this guard verifies the numerical implementation at these conditions; it does not prove semantic faithfulness or global ranking stability.

`scripts/likelihood_pilot.py` rejects duplicate sample inputs, verifies exact fresh target hashes and development/group control exclusions, freezes carrier/model/adapter/code/input/manifest hashes, and checkpoints one complete cell at a time. Resume rejects incompatible configurations or duplicate completed cells.
