## Initial prototype and principal risks

### 1. Separate extracting, matching, rewriting and scoring

Begin with verbatim generated bullets as the scoring atoms. Atomic-claim extraction, semantic equivalence and rewriting are distinct operations: an extracted or edited sentence can change meaning and can receive a different reconstruction vector. Preserve original sample/bullet IDs, original text, transformations and their versions. Never transfer an original bullet's AR vector or score to rewritten text without re-encoding it.

If the first consensus prototype uses whole bullets, name it bullet consensus. Claim-level consensus requires an explicit extraction stage and an audit of lost qualifiers, split relations and invented information. This can be added after observing the first failures; it need not be fully specified before any pilot.

### 2. Conservative semantic matching

Start with deterministic normalization that preserves negation, numbers, units and argument order. Treat aliases conservatively. A semantic match must preserve the proposition in both directions: a broader statement and a narrower statement are not automatically equivalent. Do not equate topic similarity with proposition identity.

Do not build clusters by unrestricted connected components of pairwise similarities. A matches B and B matches C does not establish A matches C. Require compatibility with every existing member, or keep separate clusters when uncertain. Record order dependence and retrieval misses. Count at most one vote per original draw, even when that draw repeats or paraphrases the claim. Divide by the full number of sampled draws; agreement is not calibrated correctness.

Embedding retrieval, if introduced, only proposes pairs. A text-only equivalence checker may inspect the candidate propositions, but not benchmark answers, transcripts, verdicts or activation scores. Cache exact requests and responses. Sample false merges and missed matches before scaling; an all-pairs LLM pipeline over every cell can dominate cost.

### 3. Define fixed-pool greedy selection precisely

For a target vector and already encoded candidate columns, one defensible prototype tries each remaining candidate, refits nonnegative coefficients over the enlarged selected set, and chooses the greatest improvement in the declared reconstruction objective. Refit again after each addition; stop at the output budget or a development-chosen marginal rule. Record centering, whitening, regularization and zero-denominator behavior.

Call this greedy NNLS subset selection unless its selection step actually follows a specified OMP variant. Classical correlation-based OMP and candidate-by-candidate refitted NNLS are different algorithms. Optional swap search must state whether every proposed swap gets a full refit and which objective accepts it. Neither algorithm proves that a selected phrase is true.

Once the fixed pool's text and AR vectors are cached, additional greedy rounds and swaps require linear algebra, not external LLM calls or fresh O-lens generations. Initial generation and AR encoding still cost GPU work. New, extracted or rewritten text requires new encoding. Semantic matching calls are a separate cost, not part of NNLS itself.

### 4. Defer residual-conditioned generation

A residual after whitened reconstruction is not automatically an activation drawn from the O-lens training distribution. The inverse transformation, mean handling, scaling, layer and injection normalization must be explicit; dividing a small residual to a fixed injection norm can amplify noise. Do not silently feed whitened residuals into a raw-activation interface.

Treat residual resampling as a separate exploratory method after the fixed-pool prototype. Score its final combined output against the original target and record every extra generation/encoding call. Include equal-candidate and measured-compute comparisons; repeated improvement in the residual objective does not establish semantic improvement.

### 5. Keep evaluators distinct from inference processors

The hallucination evaluator may use its documented transcript context. An inference-time extractor, matcher, editor or text-consistency checker must not inherit that context, benchmark labels or previous verdicts. State exact input fields for every processor and classify API calls as inference processing versus evaluation. Cache keys include exact rendered text, model/settings and prompt/schema version. A context-aware extension is a separately labeled arm.

### 6. Compare resources and finish honestly

Test combinations against each component, the full combination with each component removed, and same-pool best-of-N. Hold available candidates and final output budgets fixed; separately show actual generation, encoding, matching, selection and judging costs. Equal candidate count is not equal GPU time. Track API dollars, GPU-hours and elapsed latency independently.

Use the first runs to identify the bottleneck and refine a natural prototype. Set bounded development variants before validation; avoid searching many matching thresholds or residual recipes on test examples. Forecast against the 20-hour target after measured throughput. Unrun methods are incomplete/time-limited, not failed prerequisites or negative results.

## Final document review and resolved findings

Reviewed `docs/METHODS.md` independently after the author incorporated the design feedback. The final specification makes the stage boundaries, access restrictions, algorithm names and cost categories concrete while retaining provisional development defaults.

The document now distinguishes verbatim-bullet scoring from decomposed claims, requires provenance and re-encoding after text changes, uses all-member semantic compatibility rather than unrestricted transitive clustering, and counts support across distinct original samples. It separates optional helper calls from local generation/encoding and answer-aware evaluation. Fixed-pool D performs candidate-by-candidate NNLS refits without new language-model calls, and is explicitly distinguished from classical OMP. E2 separates labeled diagnostics from candidate-only inference alternatives. F has a declared nonjudge acceptance objective; G requires scale/rank calibration and does not claim agreement establishes truth.

Three final concrete issues were identified and resolved:

1. **Fit-cache identity was underspecified.** The draft grouped vectors and target-dependent coefficients/scores under text/layer/AR/whitener keys. The final table separates vector keys from fit keys. Fits include target-activation hash, selected candidate IDs/order, vector keys and solver/objective settings; E also includes control-bank identity. Gram matrices use the complete ordered vector keys. This prevents incorrect reuse across targets or selections.
2. **Extra editing compute needed its own comparator.** Sharing the original pool does not equalize F's extra proposals and encodings with A. The final F section explicitly compares that extra work with more independent A samples or equivalent measured compute, in addition to matched candidate/output controls.
3. **Residual normalization could amplify numerical noise.** The final optional residual-resampling section includes a development-calibrated near-zero norm cutoff before unit normalization, retains original-target scoring, and treats the derived input as potentially outside the training distribution. It remains a separate, costed extension rather than part of fixed-pool D.

The final recheck verified all three changes in the written document. No substantive specification issue remains from this review. The selected helper, semantic-matching accuracy, whitening inversion, numerical solver, throughput and actual quality improvements are still untested. The 20-hour target remains a forecast to update after measured work; it does not convert omitted methods into negative results or completed coverage.

No data generation, training, model calls, paid evaluation or GPU jobs were performed for this methods review.

## 2026-10-09 addendum: same-cell scope and reader overview

**Status:** Rechecked the new PLAN/METHODS sections only; scope clarifications accepted. The reader-overview material adds no mandatory method or benchmark.

The updated procedures keep candidate pools, consensus votes and selected evidence within one item/layer/position cell. Independent batching and exact-key global computation caches remain allowed; neither transfers support votes across cells. Cross-cell summaries are excluded from inference selection, and the benchmark's official aggregation follows independent cell readouts. Each cell's development/calibration control IDs and seed are frozen and reused across methods.

Existing-cell layer/position heatmaps are descriptive diagnostics with counts and missingness. They neither authorize new captures nor permit choosing layers from test outcomes. Mean pooling across cells, joint multisite readers and new benchmark data remain deferred. A residual computed from the original activation adds no new source observation, while changing the input distribution and generation cost; the earlier residual safeguards still apply.

## 2026-10-09 decision addendum: initial sample cap and faithful processing

The initial workflow now caps the shared pool at **32 O-lens samples per activation**. This supersedes earlier 64/128 expansion recommendations and defers fresh residual sampling. Greedy NNLS additions, refits and swaps over the cached pool remain allowed; they are numerical work, not new sampling rounds.

Keep primary output bullets verbatim. The default helper returns labels and source IDs, not rewritten claims. Split or rewritten variants remain separate ablations with fresh encodings. A false semantic merge can lend an incorrect representative the votes of different claims, so source copying alone does not establish faithful interpretation; preserve conservative all-member matching and distinct-draw counting.

Blocking helper calls use Standard Luna; background asynchronous work uses Flex. The judge remains Luna. A local adapter-disabled base-Qwen helper is only a planned comparison if a suitable runtime is verified, with capture/injection hooks also disabled and candidate-only text inputs. Freeze the selected helper per experiment after measuring equivalence errors and full-pipeline latency, including tails and retries. Shared-base biases and GPU opportunity cost remain relevant.

An earlier advisory described local Qwen as already available; that availability was not verified and is not assumed here. Neither local nor hosted speed superiority has been established. No inference, helper calls, paid evaluation or jobs were run for this addendum.
